# Kill Switch Client – Stage 3B

Stage 3B exercises the real `KillSwitchClient` process boundary against the
root-owned restricted helper, graphical Polkit, and real nftables transactions.
All firewall operations remain confined to temporary network namespaces.

## Real path under test

```text
unprivileged Python client
  -> /usr/bin/pkexec --disable-internal-agent
  -> root-owned stage-3 test bridge
  -> temporary client network namespace
  -> installed restricted helper
  -> nftables test table
```

The bridge is test-only. Its filename contains the numeric laboratory token,
which selects exactly one matching `pia-h3-client-<token>` namespace. It accepts
only the literal arguments generated by the client for the fixed test scenario.

## Scenarios

The integration harness validates:

- deliberate Polkit denial is reported as `AuthorizationDeniedError`;
- denial leaves the namespace and host firewall unchanged;
- authorized `enable` returns a verified active state;
- `status` observes the same verified state through a separate process;
- atomic endpoint and interface replacement through the client;
- incremental endpoint addition and removal;
- deliberate `disable` returns a verified disabled state;
- malformed helper output is rejected by the real subprocess client;
- a real subprocess timeout is reported separately;
- temporary probes, bridge, helper installation, namespaces, and tables are
  removed afterward.

## Safety boundary

The real host helper table is checked before and after the test. The bridge and
probes are installed only under fixed root-owned test paths, accept no arbitrary
commands, and are removed by explicit non-recursive cleanup.
